## 审计链服务端硬化（SEC-007/SOD-06，接上节）

### 缺陷
- R2「单文档全量 PUT」两大硬伤：① `PUT /api/state` 可覆盖 data.audit（恶意清空审计链，违反 SOD-06）；② 并发覆盖丢失（无乐观锁，后端原注释自认「最后一次写生效」）。

### 修复（domain 零改动，聚焦 infra）
- `server/index.js`：审计链独立存 `audit.json`；新增 `GET /api/audit`（含链校验）、`POST /api/audit`（服务端权威重算哈希，append-only）、`POST /api/audit/seed`（空链播种）；`PUT /api/state` 加 `rev` 乐观锁（expectedRev 不匹配→409）。
- `app/src/infra/repo.ts`：新增 appendRemoteAudit/seedRemoteAudit。
- `app/src/store/app.ts`：log() 审计 append 走独立 POST /api/audit；persist() 带 rev 乐观锁；syncFromBackend() 增审计链播种。

### 核心机制
- 服务端复刻前端 domain/hash.ts 的 stableStringify + 标准 SHA-256（逐字节验证一致 `9e207199…46ca`），append 不信任客户端，服务端重算 prevHash/rowHash。
- 审计从 state 写路径剥离，全量 PUT 无法篡改审计链（实测：恶意清空 data.audit 后服务端 audit.json 仍 40 条连续）。

### 关键踩坑
- 后端联调引入的异步 syncFromBackend fetch 链（health→state→audit/seed）导致 Playwright `networkidle` 判定被干扰（audit/seed 409 响应后连接不释放），smoke/e2e 卡死 3m46s。
- 修复：smoke.cjs/e2e-click.cjs 的 `waitUntil: 'networkidle'` → `'domcontentloaded'`（SPA hash 路由下更可靠）。修正后 smoke 21s、e2e 17s。

### 门禁
- vue-tsc 0 error、vitest 93/93、build 5.30s（主包 1175.82kB）、smoke 71/71（联调 21s）、e2e 31/31（联调 17s）。
- 审计链一致性：服务端 48 条 = 本地 48 条，chainOk:true，rev=9 递增正常。

### 铁律沉淀
- 审计链权威在服务端：append-only + 哈希链连续性必须服务端结构保证，禁止依赖前端自觉。
- 哈希算法单一权威 + 可跨端复刻：前端 domain/hash.ts 与服务端复刻须逐字节一致，任一端改动须两端同步回归。

- `tests/personSearch.spec.ts` +10 例。
