# 测试报告模板与结果归档 SOP

> 配套 M1 里程碑。统一四协议测试结果上报与归档规范。

## 1. 报告要素（每条测试套件）

| 要素 | 必填 | 说明 |
|------|------|------|
| 测试标题 | ✅ | 套件名 + 协议 + 测试项范围 |
| DUT 信息 | ✅ | 型号 / 固件版本 / 软件版本 |
| 环境信息 | ✅ | USB v1 型号 / 驱动版本 / CANoe 版本 / 通道映射 / 波特率 / 采样点 / 终端电阻 |
| 执行时间 | ✅ | 起止时间戳 |
| 用例结果汇总 | ✅ | PASS / FAIL / SKIP 计数 + 覆盖率 |
| 逐用例明细 | ✅ | 用例 ID / 结果 / 判据 / 备注 / Trace 链接 |
| 波形/Trace | ✅ | 关键帧波形截图或 Trace 文件链接 |
| 未闭环项 | ✅ | 失败/跳过项的整改状态 |

## 2. 结果归档命名规范

```
日期_固件版本_测试类型[_DUT型号].扩展名
例：20261103_v1.0.0_smoke-can.trace
    20261103_v1.0.0_consistency-canfd.html
```

- 测试类型枚举：`smoke`（冒烟）/ `consistency`（一致性）/ `conformance`（符合性）/ `fault`（故障注入）/ `regression`（回归）。

## 3. 结果目录结构

```
results/
├── hardware-ledger.md          # 硬件与通道台账（M1-1 交付）
├── 2026-11/                    # 按月归档
│   └── 20261103_v1.0.0_smoke/
│       ├── report.html         # 汇总报告
│       ├── *.trace             # 原始 Trace
│       └── summary.md          # 结论 + 未闭环项
```

## 4. 判定与回退验证纪律

1. **FAIL 必须可复现**：记录复现步骤 + Trace 关键帧 + 环境基线。
2. **回退验证**：每条用例先注入已知违规样本断言 FAIL，再放行正确样本断言 PASS，杜绝零缺陷假阳性。
3. **参数调整留痕**：Response Timeout / Frame Slot Time / 采样点等调整须记录调整原因与前后结果。
4. **硬件校准**：LIN 收发器建议每半年示波器校准一次波形电平与位定时。
