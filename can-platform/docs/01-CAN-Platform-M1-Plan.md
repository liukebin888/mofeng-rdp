# CAN/CAN FD/CAN XL/LIN 总线测试平台 — M1 里程碑计划

> 立项基线文档 · 版本 M1-0.1 · 2026-11-03
> 项目负责人：留总 ｜ 交付周期：40 周（M1 → M3）

## 1. 项目定位

构建覆盖 **CAN 2.0 / CAN FD / CAN XL / LIN** 四种车载总线的**自动化测试平台**，用于汽车电子零部件（ECU/控制器）的总线一致性、协议符合性、故障注入与网络管理测试。

**技术栈（已定）**：
| 维度 | 选型 | 说明 |
|------|------|------|
| 测试执行 | CANoe 12（Vector） | 报文收发、Trace、诊断、总线分析 |
| 测试设计 | vTESTstudio | 图形化/表格化测试序列、参数化用例、一键编译导出 |
| 脚本语言 | CAPL | 底层激励/仿真/故障注入回调 |
| 硬件接口 | 多硬件兼容（HAL 抽象层） | Vector VN1600/VN1630/VN7640 + 自研 USB-to-CAN，统一总线接口屏蔽差异 |
| 故障注入 | VN6501 / VH6501（选配） | 位级/报文级错误注入（M2 引入） |
| 报告 | CANoe HTML Report + 自定义模板 | 含 Trace 波形、时间戳、DUT 版本 |

> **硬件兼容需求（需求方拍板）**：平台须兼容 Vector VN1600/VN1630/VN7640 系列接口卡及自研 USB-to-CAN 适配器。因各型号协议能力边界不一致（CAN XL 仅 VN1641/VN1670 支持；VN7640 无 CAN XL；VN1641 无 LIN），引入**硬件抽象层（HAL）**做能力探测 + 统一总线接口 + 优雅降级，详见 `docs/04-Hardware-Abstraction-Layer.md`。

## 3. M1 详细计划（第 1–8 周）

### 3.1 M1 目标

M1 不追求「覆盖所有测试项」，而追求**把从「上位机 → USB v1 → 总线 → DUT」的链路彻底打通**，并用四条冒烟用例验证四协议的收发、采样点、位定时与报告输出闭环。M1 出口是可复用的工程脚手架 + 测试规范 V1 + 冒烟报告。

### 3.2 M1 任务分解（WBS）

| # | 任务 | 周期 | 交付物 | 依赖 |
|---|------|------|--------|------|

| M1-2 | CANoe 12 工程搭建：数据库导入（DBC/ARXML/LDF）、节点/通道配置 | 第 1–2 周 | 基础 .cfg 工程 | M1-1 |

### 3.3 M1 关键交付物

1. **硬件与通道台账**（`results/hardware-ledger.md`）— 多硬件兼容清单、协议能力矩阵、固件/驱动版本、通道映射、终端电阻状态。
2. **硬件抽象层设计**（`docs/04-Hardware-Abstraction-Layer.md`）— 统一总线接口 + 能力探测 + 优雅降级。
2. **CANoe 基础工程**（`toolchain/canoe/`）— 四协议通道配置、数据库导入、仿真节点。
3. **vTESTstudio 测试工程脚手架**（`toolchain/vteststudio/`）— 套件分层目录、参数化用例模板。
4. **CAPL 公共库**（`toolchain/capl/`）— 激励、断言、结果上报、错误注入钩子。
5. **四协议冒烟用例**（`test-specs/`）— 每条用例含目的/前置/步骤/判据/预期报告。
6. **测试规范 V1**（`docs/02-Bus-Test-Spec-V1.md`）— 测试项分层 + 判据 + 优先级。
7. **报告模板与归档 SOP**（`docs/03-Report-Template.md`）。

## 4. M1 风险与依赖

| 风险/依赖 | 等级 | 影响 | 缓解措施 |
|-----------|------|------|----------|
| 多硬件协议能力不一致（CAN XL 仅 VN1641/VN1670） | 🔴 高 | 选错卡跑 CAN XL 用例假 FAIL | HAL 能力探测 + 缺能力 SKIP，严禁假 PASS |
| 自研 USB-to-CAN 驱动/DLL 接口未定 | 🟡 中 | Adapter 无法落地 | 先留 Adapter 接口骨架，待自研驱动到位补齐 |
| CAN XL FAST 模式（PWM 编码）需 CANoe 19+ | 🟡 中 | CAN XL 数据域高速测试受限 | 确认 CANoe 版本；不支持则 M1 仅覆盖 SIC 模式 |
| LIN 唤醒脉冲/NAD 配置边界 | 🟡 中 | LIN 冒烟误判 | 冒烟前先用 Diagnostic 面板手动验证 NAD 与链路 |
| 终端电阻匹配（120Ω）/ 采样点配置错误 | 🟡 中 | 位定时/振铃测试失真 | 通道自检阶段记录终端电阻与采样点基线 |
| DUT 样件未就绪 | 🟡 中 | 冒烟无真实被测件 | 用 CANoe 虚拟节点 / 回环模式先行验证链路 |

## 5. M1 出口判据（Gate）

- [ ] 四协议（CAN/CAN FD/CAN XL/LIN）各 ≥1 条冒烟用例在 CANoe 中执行通过，生成含 Trace 的 HTML 报告；
- [ ] 测试规范 V1 完成，测试项分层 + 判据 + 优先级齐备；
- [ ] 工程脚手架可被 M2 直接复用（套件分层、参数化、CAPL 公共库）；
- [ ] 硬件台账记录 USB v1 型号、驱动、通道映射、终端电阻；
- [ ] 所有结果归档遵循统一命名规范（日期_固件版本_测试类型）。
